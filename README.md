# 음성 받아쓰기 실습 기록 (faster-whisper)

30초짜리 음성 하나로 **설정을 한 번에 하나씩만 바꿔 가며** 받아쓰기 품질이 어떻게 달라지는지 잰 기록입니다.
실습일: 2026-09-19

> **먼저 읽을 것 — 아래 CER 수치는 잠정값입니다.**
> 손으로 받아 적은 정답이 아직 없습니다. 지금 기준이 되는 `testvoice_answer.txt` 는
> 받아쓴 결과에서 옮겨 적은 **초안**이라, 모델이 스스로를 채점한 셈입니다.
> 설정 사이의 *상대 비교*에는 쓸 수 있지만, **절대 정확도로 읽으면 안 됩니다.**
> 정답 30초를 손으로 받아 적고 다시 돌리면 그때부터 의미 있는 숫자가 나옵니다.

## 가장 크게 좋아진 것

**고유명사 지정 (`--terms "벤지,호주,광산,오일 앤 가스,메카닉 피터"`)**

| | 기준 (2번) | 고유명사 지정 (7번) |
| --- | --- | --- |
| 회사·업계 용어 | `오랜 게스` | `오일 앤 가스` |
| 직무명 | `메카니크 퀘터` | `메카닉 피터` |
| 사람 이름 | `Benji` | `벤지` |

**왜 통했는가:** faster-whisper 의 `hotwords` 는 매 구간 프롬프트에 붙어서, 모델이 그 단어를 후보로 계속 들고 갑니다.
`initial_prompt` 과 달리 첫 구간에서 끝나지 않습니다.

**업무에 옮길 때:** 모델이 모르는 말(사내 시스템 이름, 제품 코드, 영어 약어)일수록 효과가 큽니다.
받아쓰기 전에 그 목록부터 만드십시오. `--terms-file` 로 파일에서 읽을 수 있습니다.

## 오히려 나빠진 것

이 칸이 이번 실습에서 가장 쓸모 있었습니다.

### 1. 음성을 손볼수록 나빠졌다

손본 단계 셋이 **전부** 기준보다 나빴습니다.

| 단계 | CER | 무슨 일이 일어났나 |
| --- | --- | --- |
| 무음절삭 | 11.33% → **18.00%** | 조각이 5개에서 8개로 잘게 쪼개지면서 문맥이 끊겼습니다. 30초 내내 쉬지 않고 말해 잘라낼 무음이 **0.11초**뿐이었는데도 손해만 봤습니다. |
| 크기평탄화 | 11.33% → **18.00%** | 조용한 구간을 끌어올리면서 잡음도 같이 커졌습니다. |
| 잡음억제 | 11.33% → **12.67%** | 스펙트럼 차감이 잡음과 함께 음성 정보도 깎았습니다. |

**교훈:** 깨끗한 녹음에는 손대지 마십시오. 전처리는 문제가 있는 녹음을 되살리는 수단이지, 기본값이 아닙니다.
붙이기 전에 **반드시 기준과 재서 비교**하십시오.

### 2. 16kHz 단일채널 변환은 효과가 정확히 0이었다

1번과 2번 실행의 받아쓴 글이 **글자 하나까지 같았습니다.** faster-whisper 가 파일을 읽을 때 내부적으로 똑같은 변환을 이미 하기 때문입니다.
남들이 다 한다고 넣은 단계가 아무 일도 안 하고 있을 수 있습니다.

### 3. 가장 좋았던 설정조차 새 오류를 만들었다

고유명사 지정은 CER 을 낮췄지만, 동시에 멀쩡하던 곳을 망가뜨렸습니다.

| | 기준 (2번) | 고유명사 지정 (7번) |
| --- | --- | --- |
| | `메카닉 피터로 일을 했었고` | `메카닉 피터로 **일어났었고**` |
| | `호주에서 광산 님을 했었고요` | `호주에서 **광산이를** 했었고요` |

**평균이 좋아졌다고 모든 자리가 좋아진 것이 아닙니다.** 숫자만 보고 넘어가면 놓칩니다.

### 4. 아무도 맞히지 못한 곳, 한 번만 맞은 곳

- `현구에서` → 7개 실행 **전부** 틀렸습니다. ("한국에서"로 추정) 모든 설정이 같은 곳에서 무너지면 그건 설정 문제가 아니라 **발음·녹음 문제**입니다.
- `광산 일을` → 가장 나쁜 점수를 받은 **무음절삭(4번)만** 맞혔습니다. 전체 점수가 나쁜 설정도 특정 자리는 더 잘 잡을 수 있습니다.

## 요약본만 보고는 못 잡았던 오류

무음절삭(4번) 실행 결과:

```
[00:00:04.380 --> 00:00:10.380] So, I was working in Australia and I'm back in Korea soon.
[00:00:10.380 --> 00:00:13.380] I know what I'm going to do in South Korea and beyond.
```

- **`soon` 은 원문에 없습니다.** 다른 6개 실행 어디에도 나오지 않습니다. 그런데 문장은 완벽하게 읽히고, 요약하면 "곧 한국으로 돌아온다"가 됩니다. 원문을 나란히 놓지 않으면 잡을 방법이 없습니다.
- **`I know what I'm going to do`** — 문맥상 `I don't know` 였을 가능성이 있습니다. 부정어 하나가 빠지면 뜻이 정반대가 되는데, 문장은 멀쩡합니다.

이런 오류의 공통점: **틀린 티가 나지 않습니다.** 받아쓰기 오류는 깨진 글자로 오지 않고, 말이 되는 다른 문장으로 옵니다.
계약 조건이나 금액을 받아쓴다면 이것이 무엇을 뜻하는지 생각해 보십시오.

## 남은 일

1. **30초를 손으로 받아 적기.** 이게 없으면 위 숫자는 전부 잠정입니다.
2. **업무 용어로 다시 해 보기.** 사내 시스템 이름, 제품 코드, 영어 약어를 일부러 말하고 녹음해서 무엇이 무엇으로 바뀌는지 보십시오.
3. **견딜 수 있는 오류율 정하기.** 숫자와 근거 한 줄.
4. **녹음 방법 정하기.** 이번 파일은 마이크·거리·앱을 적어 두지 않아 재현할 수 없습니다. 다음부터는 같이 기록하십시오.

## 쓰는 법

```bash
# 기준 실행
python transcribe.py 음성.ogg

# 한 번에 하나씩만 바꾸기
python transcribe.py 음성.ogg --denoise
python transcribe.py 음성.ogg --trim-silence
python transcribe.py 음성.ogg --normalize
python transcribe.py 음성.ogg --terms "사내용어1,제품코드2"
python transcribe.py 음성.ogg --model medium

# 정답과 대조해 글자 오류율까지
python transcribe.py 음성.ogg --ref 정답.txt
```

- 결과 파일 이름에 켠 단계가 드러납니다: `testvoice_small_RD_20260919-032424.txt`
  (**R**=16k모노, **D**=잡음억제, **T**=무음절삭, **N**=크기평탄화)
- 다시 돌려도 덮어쓰지 않습니다. 실행 시각이 이름에 들어갑니다.
- 실행마다 `out/runs.tsv` 에 설정과 결과 파일 이름이 한 줄씩 쌓입니다.
- 시각은 무음을 잘라내도 **원본 음성 기준**으로 되돌려 적습니다.

### 구성

| 파일 | 역할 |
| --- | --- |
| `transcribe.py` | 전체 흐름, 옵션, 실행 기록 |
| `audio_prep.py` | 음성 손보기 4단계 + 원본 시각 되돌리기 |
| `cer.py` | 글자 오류율 계산, 틀린 자리 찾기 |

띄어쓰기와 문장부호는 빼고 세고, 바꾸기는 한 번으로 셉니다.

### 설치

```bash
pip install faster-whisper
```

ffmpeg 같은 별도 프로그램은 필요 없습니다. 오디오 디코딩은 PyAV 가, 손보기는 numpy 가 합니다.
